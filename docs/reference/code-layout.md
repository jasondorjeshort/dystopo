# Code layout: modules and where things live

The module map with the detail that agents need when they edit a module. The system map is `../ARCHITECTURE.md`; the Kotlin conventions are `.claude/rules/kotlin.md`.

## Modules

- `shared/` — Kotlin Multiplatform core (JVM and Android targets; iOS later). `commonMain` must stay pure Kotlin: **no `java.*` imports**, so it compiles for every target. Platform-specific pieces (image decoding, HTTP, zlib) are injected through small interfaces such as `ByteRangeSource` and `Decompressor`. T80: the elevation readers live in `shared/.../sources/elevation/` (3DEP, lidar, Copernicus, the national sources, geoids, `BestSource`, `RemoteTiff`, `Lerc2`); their platform pieces are `expect`/`actual` in `Platform.kt` (`SourceFiles` file cache, `IoPool`, `parallelForEach` on a fixed 16-thread pool, zlib, the default HTTP client) with the JVM and Android actuals in `src/jvmCommonMain` and the HTTP client in `jvmMain`/`androidMain`. `SourceIo` holds the cache root (`Caches.root` on the server sets it), the replaceable HTTP client, the `beforeNetwork` hook (`Http.beforeNetwork`), and the phone's pools (`tiffPool`, `decodedBlocks`; null on the server). T269: the range-block cache (`CachedRangeSource` in `RemoteTiff.kt`, one directory per remote file with `<offset>-<length>.bin` blocks) keeps the file's validator in `validator.json` beside them (`etag` verbatim, `lastModified`, `length`, `checkedAt`), taken from the first range response; later range GETs send it as `If-Match` (all eight hosts honour it, 2026-11-10: the 3DEP 10 m and 1 m, Copernicus, HRDEM and LINZ S3 buckets, swissALTI3D, BEV's Apache and the PROJ CDN for the geoid grids; Kartverket reads a WCS, not this cache). A 412, or a response with another ETag, drops the whole directory and the open `RemoteTiff` reopens and reads again; a validator checked over a day ago gets one HEAD in the background (a client without headers or HEAD, the phone's and `SourceBudget`'s, compares the cached header block `0-65536.bin` with a fresh read instead); a directory with blocks and no `validator.json` (cached before T269) gets one check and is dropped when the file's Last-Modified is newer than its oldest block. A check never holds a read up; offline it changes nothing and is tried again 15 minutes later. A decode error on cached blocks forces one recheck per file and process, then one retry after a drop. Counters: `cellsChecked`, `cellsDropped`, `ifMatch412` per source beside `rangeRequests`, and process totals with `checkFailures` in `RangeValidation.json()` (`SourceTiming.json()` `rangeCache`, the phone's `GET /online` sources; `render`'s `rangeCache.*`). One behaviour, no setting (the day is a constant). serverlib keeps the old class names as type aliases (`ElevationSources.kt`); for a nested type such as `ElevationSource.Result` import the shared class.
- `devtool/` — JVM command-line tool that runs shared-core features and prints JSON reports. JVM-only code (image I/O, PNG rendering) lives here.
- `serverlib/` and `server/` — the server pieces (`LiveTiles`, `BuildRoutes`, `ServeStatic`, `SyncRoutes`, `PackCatalog`, the elevation sources under their old names; package `...dystopo.server`) shared by `devtool serve` and the standalone server (`./gradlew :server:installDist`, config file, `/catalog`, `/healthz`, `/metrics`, token, body and time limits, a rotating JSON log, Dockerfile): see `docs/SERVER.md`, whose Operations section covers running it for real; `python -I tools/server-probe.py` (73 probes, must leave the server alive) and `tools/server-soak.ps1` (hours under load, SVG chart) are the T82 checks, and the nightly workflow runs a 20-minute soak.
- `tilebuild/` — JVM-only build tool: OSM extract → PMTiles via Planetiler (heavy dependencies stay here, out of devtool). `./gradlew :tilebuild:run --args="--extract liechtenstein --out out/liechtenstein.pmtiles"`; first run downloads ~1.45 GB of aux data into the cache.
- `tools/` — repo tooling: `PrivacyCheck.java` and the git hooks in `tools/git-hooks`; `user-text-check.py` (T104, run by `./gradlew check` as `userTextCheck`), which fails when user-visible text names another mapping product listed in `user-text-names.txt`.
- `tools/site/` — the home site (ADR 0052, `docs/reference/home-site.md`): `install.ps1` (install, `-Update`, `-Firewall`, `-HttpsPort`, `-Uninstall`; server and Caddy as two scheduled tasks), `status.ps1`, the `Caddyfile` and `server.example.json` templates. `tools/ports.ps1` names every listening TCP port with its owner and, for java, its main class (`-SelfTest`).
- `areas.json` — public named test areas. Personal areas go in `devtool.local.json` (gitignored, same format, main checkout only).
