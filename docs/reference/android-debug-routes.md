# Android debug routes

Debug builds only, on the debug port (`android-app.md`, Loopback token). The KDoc at the top of each `*Routes.kt` file is the full reference for its routes; this page is the map. Tracks and sync: `android-tracks-and-sync.md`; direct sources, updates and first run: `android-online.md` (T247: a failed update check's kind, status code and attempts in `GET /update`, the row's fold by `POST /update/fold`).

## Endpoints

Debug endpoints (debug builds only, on the debug port; `curl -H "X-Dystopo-Token: $T" http://localhost:<forwarded port>/...`). They run on their own small thread pool, so they answer while contour tiles generate:
- `GET /health`: packs, server load (`rejected` counts per reason, tile and debug pool queues), map state. `map.idle` means style loaded, MapLibre's `isFullyLoaded`, last frame complete, no tile pending at the server, no camera move and no new frame for 500 ms; `map.notIdleBecause` names the blockers (`styleLoading`, `animating`, `pendingTiles`, `notFullyLoaded`, `frameNotFullyRendered`, `rendering`, `settling`); `map.lastScreenshot` says how the last screenshot settled; T138: `map.styleLoads` counts the styles set on the map since the process started (a tile that came without a style reload leaves it unchanged).
- `GET /screenshot[?wait=ms][&mode=window][&stable=0]`: PNG of the map (MapLibre snapshot). It waits for idle and then until two snapshots in a row agree, so it never returns a half-loaded map; `stable=0` skips the pixel check, `wait=0` captures at once. `mode=window` copies the map surface and draws the Compose overlays on top. **View it**, like the devtool PNGs.
- T224, **the map screen's layout** (`LayoutRoutes.kt`, `MapLayout.kt`, shared `ui/OverlayLayout.kt`; `android-app.md`, The map screen's layout): `GET /layout` lists every element of the map as drawn now (`elements`: `id` from ADR 0053's controls inventory, or the manifest name for `scaleBar`, `compass`, `onlineCard` and `firstRunCard`; `name`, `controls`, `rectPx`, `state` `shown`, `compact` or `hidden`, `reason`, and `within` for an element inside another by design, the Online chip's card in `M8`). T241: every rectangle is read from the element's `Modifier.control` node as it was placed in the last layout pass (`MapLayout.kt`, `MeasuredControls`), none worked out from an edge; the compass's from MapLibre's view; `measure` has the nodes' pass counter (`pass`, `placements`). Also the `window` and `fontScale`, `onlineCard` (T236: `open`, `rectPx`), `overlaps` (the pairs that share at least a whole pixel, never an element and the one it lies within: `a`, `b`, `aName`, `bName`, `sizePx`) and `rule`, the placement the pure function made from the same sizes (`elements`, `sideColumn`, `cardColumns`, `buttonsDrawn`, `entriesDrawn`, its own `overlaps`, always empty, and `differs`, where it would change a state).
