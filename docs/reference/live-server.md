# The browser demo, live world mode and the JVM stand-in for the phone

The viewer agents and the owner use, and how to check it headlessly. Ports and the coordinator's own servers are in `machines.md`; server deployment is `../SERVER.md`.

## Browser demo

Browser demo (MapLibre over our DEM tiles and OSM PMTiles): generation commands are at the top of `tools/demo/index.html`; then `python -I tools/demo-server.py 8765` and open http://localhost:8765/tools/demo/. Units there are a stored preference (localStorage), seeded by region on first open, changed with the Units select; `?units=ft|m` overrides one load. The demo tour (`--views-file tools/demo-tour.txt`) must pass against both this page and `devtool serve` (its `req=` names are roles mapped to each style's layers). **Agents check it headlessly** with `python -I tools/demo-check.py --view <z/lat/lon> --out out/check.png` (Playwright + Chrome): exit 0 means the map went idle with no console errors, page exceptions, or failed requests; the JSON lists rendered feature counts per layer and the screenshot path, so you can see what a user would see. A zero count on a layer that should have features is a bug, not a style choice.

## Live world mode

**Live world mode:** `./gradlew :devtool:run --args="serve --live --port 8687"` and open http://localhost:8687/ (the same demo page). Packs in `out/` (and `--dem`/`--osm`) answer the tiles they hold; everywhere else the DEM is rendered on request from the `best` source (3DEP, Copernicus, EGM2008) through the `tiles` per-tile path, contours are generated from it, and OSM base layers come from OpenFreeMap (registry id `openfreemap`; outdoors-only layers exist only inside packs). Both are cached under the cache dir (`live/`, `openfreemap/`; T74: with contours and shade in `derived/`, each byte-capped with LRU, `DYSTOPO_CACHE_CAPS=live=4096,openfreemap=2048,derived=1024` MB, `DYSTOPO_TILE_CACHE` to keep them apart from the source downloads, `/stats` `caches`), so a second view anywhere is warm; the first view of a new place takes 10 to 30 s. The box at the top right says which source the visible tiles came from (pack, live-3dep, live-copernicus, openfreemap); `Build pack here` calls `POST /build?name=&bbox=&minZoom=&maxZoom=` (see `BuildRoutes.kt`: progress at `GET /build/{id}`, cancel with `DELETE`), which writes `out/<name>-dem.pmtiles` from the live DEM and `out/<name>-outdoors.pmtiles` from OpenFreeMap tiles (OpenMapTiles schema, not the outdoors profile), serves them under `/out/` and from then on as packs. With `&profile=outdoors` (the page's Vector select) the vector pack is the real outdoors profile instead: one Overpass request for the box (cached) when it is under 0.05 square degrees, else a Geofabrik extract on disk in `cache/extracts/` or one downloaded on demand from the regions in `extractDownloads` (`DYSTOPO_EXTRACT_DOWNLOADS` for `serve`), each covered by its `.poly` polygon; a box nothing covers gets a 422, and 413 is only for a forced `source=overpass` over the cap (T66), converted and built by tilebuild in a subprocess, so run `./gradlew :tilebuild:installDist` once (and again after changing tilebuild); `&fallback=1` falls back to OpenFreeMap when Overpass refuses. Small boxes read only the ocean polygons that reach them (none inland; `waterPolygons` in tilebuild's report), so a Paradise-sized rebuild takes about 5 s warm. `GET /stats` has per-route, per-source tile counts and timings, `/phone` the phone style over the live routes. **Map options** (the phone's T47 settings) work in both `serve` modes as query parameters of `/style.json`, `/phone` and `/` (the demo page also has a Map options section that writes them to the URL): `hillshade=off|single|multi`, `hillshadeIntensity=0..1`, `slope=on`, `contourInterval=auto|<n>` (in the contour units), `contourLabels=sparse|normal|dense`, `night=on`, `trails|water|landcover|pois|boundaries=off`; a bad value is a 400. The style then points at `/shade/{z}/{x}/{y}.png?...` (hillshade and slope rasters from the DEM, as on the phone; `shadeGeneration` in `/stats`) and `/contours/...?interval=<n>`. Check it with `python -I tools/demo-check.py --url "http://localhost:8687/?live=1" --views "12/45.83/6.86|src=live-copernicus" "12/46.85/-121.76|src=pack"`: in live mode every view must also show hillshade and OSM features, and `|src=` checks the DEM source.

## Trip editor

**Trip editor** (T68, live mode; `tools/demo/trips.js`, routes in `RouteRoutes.kt`, docs/SERVER.md › Route planning): "Plan a trip" in the panel; with "Plan route" on, click the start and the end, click again to add a via point, drag a numbered point to move it, right-click to remove it. The card has distance, climb, descent, hike time, the profile (hover it), GPX and "Save as trip" (into the browser's own sync replica in localStorage, then pushed to the server's `/sync/push` with the Token field; a phone syncing with the server gets it). `window.dystopoTrips` scripts it. Check the flow with `python -I tools/demo-check.py --url "http://localhost:8687/?live=1" --views "12/46.85/-121.76|src=pack" --route "46.7864,-121.7366;46.8024,-121.7289;46.7960,-121.7262"` (Paradise to Panorama Point with real clicks, a via point added on the line and dragged to the third place, GPX, save and push; `route` in the JSON, screenshot `<out>-route.png`). **Long drives** (T77): `--long-route "47.6062,-122.3321;46.6021,-120.5059" [--long-route-packs 2] [--long-route-ms 10000]` clicks both ends in drive mode (`--route-mode`) and checks the route follows roads across at least that many packs within the time (`longRoute` in the JSON, `<out>-long-route.png`; needs packs covering the way in `out/`); the card says how many packs and overlay tiles the server used. Long drives search through `DriveOverlay` (docs/PLANNING.md › Routing; `GET /route?...&overlay=0` to compare).

## No device: `devtool serve` as the phone stand-in

**No device?** `./gradlew :devtool:run --args="serve"` serves the same routes from the same shared code (style, DEM with ancestor fallback, generated contours, glyphs from `cache/glyphs`) on http://127.0.0.1:8687/ with a MapLibre GL JS page, so the phone style can be checked with `python -I tools/demo-check.py --url http://localhost:8687/ --views 12.5/46.853/-121.76` (MapLibre GL JS, not Native: it catches style and tile bugs, not Android ones). `GET /stats` there gives desktop contour timings.

## Conventions for the coordinator's servers

- The coordinator's live viewer runs from the main checkout on port 8765 (`./gradlew :tilebuild:installDist` once, then `./gradlew :devtool:run --args="serve --live --port 8765"`), started by a chore agent with its PID recorded in `out/coordinator-pids.txt`. Agents read it; they never stop it and never ask it to build (`android-firstrun.py --until test` only reads its catalog).
- First-run tests use the standalone server (it binds 0.0.0.0) at the host's LAN address, not `devtool serve` (127.0.0.1 only) and not 10.0.2.2, so the private-range rule is what is tested (`android-online.md`, First run).
- A task's own server uses the ports in its brief and is stopped by its PID.
