### T96. Kept peers never rotate the sharer's code; a bounded linger (T90 verifier)
**Goal:** the T90 verifier's two defects in `share/**`, found on 2026-10-14 after T90 merged. (1) The sharer's code is rotated under the user: B keeps a peer and up to three more known codes (`MAX_CODES` 4; Forget does not retire a code); A reopens its share screen (new code); B relaunches and opens its Share screen: the launch retry spends one failure on A's gate, then discovery's `onDiscovered` tries every known code on A, the kept one again because the retry never adds it to `tried`, so five failures rotate A's code (`rotations` 1). Make the retry's wrong code count in `tried`, retire a peer's codes on Forget, try at most one stale code per discovered phone per session (and no code known to have failed against that phone), and lower `MAX_CODES` if the rest does not keep a sharer's gate under its limit.
