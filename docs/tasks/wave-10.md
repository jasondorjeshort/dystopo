### T59. Norway and Austria bare-earth elevation
**Goal:** two more national sources on the Swiss pattern, chosen for open licences and cloud-readable tiles: Kartverket's DTM (Norway, 1 m and 10 m, CC BY 4.0, GeoTIFF/COG through their WCS or the `hoydedata` download service: research which is range-readable) and Austria's ALS DTM (`geoland.at` / BEV, CC BY 4.0, 1 m, COG via the open data portal). For each: a source class with an index cache, projection in pure Kotlin (UTM 33N for Norway is already there via `Utm`; Austria uses MGI / Austria Lambert, EPSG:3416: implement the Lambert conformal conic with the MGI datum shift and test against published points), a vertical datum through the PROJ CDN grid where one exists (Norway: `no_kv_HREF2018B_NN2000_EUREF89.tif`; Austria: `at_bev_GV_Hoehengrid_V2.tif`, both CC0 or similar: check), coverage gate, feathered seams with Copernicus, registry entries, areas (`galdhopiggen` 2469 m, `grossglockner` 3798 m) in the tour. If one of the two has no range-readable open COGs, say so, do the other, and record the finding in PLANNING.
**Owns:** new `serverlib/.../NorwaySource.kt`, `AustriaSource.kt`, `shared/.../geo/AustriaLambert.kt` (+ tests), `shared/.../dem/VerticalDatum.kt` (new datums), `sources.json`, `areas.json`, the `BestSource` block, the Licensing table rows.
**Done when:** `render --area galdhopiggen --source best` and `--area grossglockner` use the new sources with summit elevations within 5 m; border seams feathered (compare at the Austria/Italy border); tour 58/58; `check` green.

### T61. Navigation mode

### T63. Cold start and tile scheduling
**Goal:** the phone's first view. On a cold start the OSM layer lands 4 to 5 s after the contours because contour generation fills the loopback server's threads, and release first-contours is 1.6 to 3.7 s. Give the loopback server separate pools for cheap pack reads (DEM, OSM, glyphs, sprites) and for generation (contours, shade, cliffs), with generation at lower priority; serve the map's visible tiles before warm-up tiles; measure with the release script (`am start -W`, first contours, first OSM, settled) over 5 cold starts before and after; a `/stats` section for queue waits per pool. Also the duplicate-decode gap from T42 (two threads missing the same DEM tile) with a per-tile in-flight map in `DemPyramid`.
**Owns:** `androidApp/.../LocalServer.kt`, `TileService.kt` (pools and priorities), `shared/.../tiles/DemPyramid.kt` (in-flight dedup), `tools/android-release.ps1` (first-OSM timing).
**Done when:** release cold start to a settled first view under 5 s on the emulator (table in the PR), OSM no longer trailing contours by more than 1 s, device tour 10/10, `check` green.
**Status: merged (PR #64).** Cold start under 5 s met; the 1 s OSM lag is not (MapLibre-side, 1.0 to 1.6 s). Follow-ups: lighter first-frame vector tiles; cliff rewrite off the OSM request path; document `server.pools` in CLAUDE.md.
