# Wave 4 (T1–T18 merged except T10)

### T19. Sources and formats sweep
**Goal:** close the recorded follow-ups in the sources and formats. (1) `CachedHttpRangeSource`: two threads fetching the same cold range must not crash on the `.part` → `.bin` move (tolerate an existing target; keep the first writer's bytes). (2) `render`, `compare` and `tour` on a grid with no data: no Infinity in JSON (null min/max), no exception; `render --area pacific` exits cleanly with a magenta image and a report saying no data. (3) Lidar is pointless when the output cell is coarse: skip the lidar index and tiles when `cellSizeMeters` > 20 m (document the threshold; `best` must give identical results where lidar wasn't contributing anyway: prove with grid digests on `rainier` z8–10). (4) TNM index fetch: retry with backoff like `Http.withRetry`. (5) `tiles` metadata and PMTiles header bounds for an antimeridian box: write GeoJSON-style west > east within −180..180. (6) `pmtiles info`/`extract` print one error line on a corrupt archive instead of a stack trace. (7) `PmtilesExtract` takes a `TileStaging` so large extracts don't hold every blob in memory; test it with a temp-file staging.
**Owns:** `devtool/.../ElevationSource.kt`, `LidarSource.kt` (not the Geoids coverage logic, which is T21's), `RenderCommand.kt`/`CompareCommand.kt`/`TourCommand.kt` (no-data handling only), `TilesCommand.kt` (bounds), `PmtilesCommand.kt`, `shared/.../pmtiles/PmtilesExtract.kt` and tests.
**Done when:** each item has a test or a demonstrated run in the PR; `tour --zooms 9,12` still 44/44; cold `render --area death-valley --zoom 9` time before/after (3); `check` green.
**Status: merged (PR #20).** Leftover: `tiles` over a zoom with no written tiles leaves NaN in `ZoomReport.elevationMin/Max` (the same JSON crash `render` had); `PmtilesExtract` re-reads a source blob when the input stored identical content at different offsets (rare, documented).
