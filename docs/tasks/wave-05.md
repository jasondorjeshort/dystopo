# Wave 5 (T1–T24 merged)

### T10 (revised). Android shell
**Goal:** phase 1 on a phone, using today's packs. An `androidApp` module (Kotlin, Jetpack Compose, MapLibre Android, min SDK 26) that shows a region pack: the DEM PMTiles (hillshade via MapLibre's raster-dem), the outdoors vector PMTiles, and **contour tiles generated on the device** from the DEM pack with the shared `Contours` + T5 MVT encoder. MapLibre Android can't read `pmtiles://`, so the app runs a small local HTTP server (loopback only) that serves `/dem/{z}/{x}/{y}.png`, `/osm/{z}/{x}/{y}.pbf` and `/contours/{z}/{x}/{y}.pbf` from the packs through the shared readers, caches generated contour tiles on disk, and also exposes the debug endpoints (`/health`, `/screenshot`, `/camera` get/set, `/stats` with tile timings and memory). The MapLibre style is derived from the same declarative style the devtool uses where practical (at least the colours and the layer set). Packs get to the device with `adb push` into the app's files dir (a `tools/android-push-pack.ps1`). The current location is shown when permission is granted. **Install the Android SDK command-line tools, platform-tools, one platform (API 35), build-tools, the emulator and an x86_64 system image under `~\Android\sdk` (approved by the owner); scripts `tools/android-sdk.ps1` (install/update, accept licenses) and `tools/android-emu.ps1` (boot headless `emulator -no-window`, wait for boot, forward the debug port, install the app).** Don't change machine-wide settings beyond that directory and `local.properties`; if hardware acceleration isn't available to the emulator, report it and use the software renderer. Add the `android` target to `shared` (keep `commonMain` pure Kotlin; the Android source set may provide the image codec and HTTP hooks the JVM one has). Add an Android section to `CLAUDE.md` (commands) and the tolerated-license handling for Android artifacts if the license check needs it (MapLibre is BSD-2; AndroidX is Apache-2.0).
**Owns:** new `androidApp/`, `tools/android-*.ps1`, the `android` target block and any `androidMain` source set in `shared/`, Android entries in `gradle/libs.versions.toml`, `settings.gradle.kts` include line, `local.properties` handling in `.gitignore` (already ignored), the Android section of `CLAUDE.md`, `gradle/licenses/*` additions if needed.
**Done when:** `./gradlew :androidApp:assembleDebug` builds; `tools/android-emu.ps1` boots the emulator, installs and launches the app, pushes the Rainier packs; `curl localhost:<port>/screenshot` returns a PNG that shows hillshade, contours and trails around Rainier (viewed and described in the PR); `/stats` reports per-tile contour generation time and memory (first numbers for the phone-footprint budget in docs/PLANNING.md); `check` green on the JVM modules (Android unit tests optional in this task).
**Status: merged (PR #24).** Verified on the JVM stand-in (`devtool serve` + `demo-check.py`) and by APK inspection; the first emulator run (recorded in the Phase 0 log) found: no text labels on the device, blank `mode=window` screenshots, no visible puck, `&copy;` in the attribution, `idle` stuck false, and 7 to 10 s contour tiles at z12 and below. Wave 6 tasks T25 to T28 cover these. Follow-ups: key the contour disk cache on the DEM pack identity (size + mtime) or clear it on `/reload` and in `android-push-pack.ps1`; add the Noto Sans glyph font (OFL 1.1) to `sources.json`; bound the loopback server queue and header count, add a slow-connection timeout; probe tile routes with huge or negative coordinates; denser contour labels on the phone; diff `MapLibreStyle` layer by layer against `DefaultOsmStyle`.

### T24. Tracks, waypoints and GPX
**Goal:** the first user-data feature, in `shared` so every platform shares it. A data model (`Waypoint`, `Track` with segments and points carrying time/elevation, `Route`), GPX 1.1 import and export (pure-Kotlin XML reader/writer good enough for GPX; also tolerate common extensions like Garmin TrackPointExtension), derived stats (distance, ascent/descent with a smoothing rule, duration, moving time, min/max elevation, pace), elevation profile sampling, and a devtool: `gpx info file.gpx` (JSON stats), `gpx render file.gpx --area|--auto-bbox --zoom 14 --osm ...` drawing the track and waypoints on the rendered map with labels (reuse the style engine's line and symbol drawing), `gpx export` round trip. Synthetic test tracks only (e.g. a generated loop over the synthetic terrain, and a hand-written GPX fixture around public Rainier trails such as the Skyline Trail, derived from nothing personal).
**Owns:** new `shared/.../gpx/**` and `shared/.../model/**` with tests, new `devtool/.../GpxCommand.kt`, one line in `Main.kt`, a tiny synthetic GPX fixture under `shared/src/commonTest/resources/`.
**Done when:** round-trip tests (parse → export → parse equal), stats tests on known geometry, `gpx info` and `gpx render` runs with the fixture viewed and described; `check` green.
**Status: merged (PR #23).** Follow-ups: waypoint labels aren't collision-checked against the map's own labels (expose placed label boxes from MapRenderer); `gpx` commands should turn `XmlException` into a one-line usage error; derive zoom from the fitted bounds instead of erroring on very large tracks; `TrackStats.bounds` is null for degenerate tracks; our ids are not preserved through GPX export (sync phase).
