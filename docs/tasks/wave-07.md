### T35. Contour tracing speed and warm-up
**Goal:** on the device z13+ contour tiles spend 170 to 500 ms in `render/Contours.kt`; cold start after install shows 2 to 3 s z12 tiles. Profile the tracer on the JVM (JFR or manual timers) and make it cheaper: avoid per-cell allocations, trace index and minor levels in one pass, reuse buffers, skip cells whose min/max exclude every level, simplify in-place. Target z13 tiles under 150 ms warm on the emulator and the 28-tile JVM sweep under 500 ms single-threaded. Add background warm-up: after install, pack activation or `/reload`, generate the contour tiles for the pack's bounds at the two lowest pack zooms in the background at low priority, reporting progress in `/stats` (`warmup`), so the first zoom-in is never cold. Goldens must not change (same contour geometry) unless the change is a deliberate, viewed simplification.
**Owns:** `shared/.../render/Contours.kt`, `ContourSimplify.kt`, `shared/.../tiles/ContourTiles.kt` (warm-up planning), `androidApp/.../TileService.kt` (warm-up scheduling); tests and a JVM benchmark under `devtool` (`contours bench` subcommand).
**Done when:** `contours bench` prints before/after timings in the PR; goldens unchanged (or regenerated, viewed and explained); emulator `/stats` after a fresh install plus zoom-in shows max contour ms under 1000 with warm-up on; `check` green.
**Status: merged (PR #35).** The z13 150 ms target is missed (about 107 to 177 ms warm); DEM decode is now the bottleneck. Follow-ups: faster or cached DEM decode (decode once per DEM tile into a shared float grid; consider a pure-Kotlin PNG decoder to skip Bitmap); extend warm-up to the first screen's z12/z13 tiles; a warm-up on/off setting; pre-empt warm-up tiles for map requests.

Record provenance and attribution in the pack metadata (registry ids incl. `openfreemap`). Cap concurrent builds and total tiles per job; refuse boxes over a configurable size with a clear error.
**Owns:** new `devtool/.../BuildRoutes.kt`, `devtool/.../DemPmtiles.kt` (reuse; small refactor allowed), new `shared/.../packs/OsmPackWriter.kt` (PMTiles from fetched tiles, with tests), `LiveTiles.kt` (shared fetch and cache), `tools/demo/index.html` (the "Build pack here" button calls `/build` and shows progress), `sources.json` only if a field is missing.

### T38. Online mode on the phone
**Goal:** the app can browse the world without a pack. A configurable server URL (default empty; debug default `http://10.0.2.2:8765` on the emulator) in settings; when no active pack covers a tile, `TileService` fetches `/dem`, `/osm` (and glyphs/sprites if missing) from the server with an on-device LRU disk cache (size-capped, evicting oldest), contours generated locally from the fetched DEM as today; the map shows an online/offline indicator and the source of the current view; "Download this region" on the map calls the server's `/build` (T37) for the current view box and hands the result to T29's downloader. Debug: `GET /online` (server, cache size, hits, fetches, errors), `POST /settings?server=`, `POST /online/download?bbox=&zooms=`. Must degrade gracefully with no network: no crashes, tiles stay blank, indicator says offline, cached tiles still serve.
**Owns:** `androidApp/.../TileService.kt` (fallback path), new `androidApp/.../online/**` (fetcher, cache, download orchestration, indicator), new `OnlineRoutes.kt`, `AppSettings` server field, `packs/` download hand-off (one call), `MapController.kt` indicator overlay (one block).
