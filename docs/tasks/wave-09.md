A new `server/` JVM module that packages what `serve --live` already does (tiles, live sources, builds, `/out/`, sync peer, attribution) behind a config file (ports, cache dir, out dir, allowed CORS origins, build limits, Overpass endpoint, optional bearer token for `/build` and `/sync`), with structured JSON logs, a `/healthz`, graceful shutdown, a pack **catalog** (`GET /catalog`: every pack in `out/` with name, bounds, zooms, profile, size, build time, provenance, a stable id and a content hash), and packaging as a runnable distribution plus a Dockerfile (eclipse-temurin base, permissive). Reuse the devtool code by moving the shared server pieces into a `serverlib` source set or module that both devtool and server depend on; devtool `serve` keeps working. Document deployment behind a TLS reverse proxy in `docs/SERVER.md`.
**Owns:** new `server/**`, new `docs/SERVER.md`, the refactor of `devtool/.../ServeCommand.kt`, `LiveTiles.kt`, `BuildRoutes.kt`, `ServeStatic.kt`, `SyncRoutes.kt` into a shared place, `settings.gradle.kts` include, `gradle/licenses/*` if needed, README deployment paragraph.

### T54. Phone-to-phone sync on a local network
**Goal:** the first peer-to-peer step. A "Share" screen that, while open, announces the device with NSD (mDNS) and listens on a LAN-bound port (not the loopback server) protected by a 6-digit code shown on screen; the other phone discovers it, the user enters the code, and the two sync both ways with the T44 HTTP transport over that link; no server involved. Also a QR code with the address and code for networks without mDNS. On emulators, test with `adb forward` and `adb reverse` so B reaches A through the host (document the recipe in the PR and CLAUDE.md). Debug routes: `POST /share/start`, `GET /share/status`, `POST /share/connect?addr=&code=`.
**Owns:** new `androidApp/.../share/**`, `ShareRoutes.kt`, manifest permissions for NSD, `shared/.../sync/**` only for a transport factory hook, `tools/android-emu.ps1` only to add a helper flag for the forward/reverse pair.

**Status: merged (PR #52).** Follow-ups: fix the CLAUDE.md claim about direct emulator-to-emulator connects; QR scanner and `dystopo://share` link handling; use paged sync on the LAN link; encrypt or key the link; merge the duplicated store wrapper with `AppSync`.

### T56. Swiss bare-earth elevation (swissALTI3D)
**Goal:** the first non-US high-resolution source, proving "best data per region" outside the US. Swisstopo's swissALTI3D (0.5 m and 2 m GeoTIFF/COG tiles, open data under the swisstopo OGD terms, attribution required; served via their STAC API) as a devtool elevation source: a per-cell index from the STAC collection cached like the TNM index, reading the 2 m product (0.5 m only at z15+ if feasible), LV95 to WGS84 reprojection in pure Kotlin (the Swiss projection formulas are published), LHN95 heights to EGM2008 through the published CHGeo2004 geoid grid or, if that grid is not freely available as a raster, a documented constant-plus-bilinear approximation with its error stated; coverage gate from the collection extent; feathered seam against Copernicus at the border (view it at the Matterhorn / Italian border); registry entry with licence and attribution; `areas.json` gains `matterhorn` and `jungfrau` with expected elevations; the world tour includes them.
**Owns:** new `devtool/.../SwissAltiSource.kt`, `shared/.../geo/SwissProjection.kt` (+ tests against published test points), `shared/.../dem/VerticalDatum.kt` (one new datum), `sources.json`, `areas.json`, `ElevationSource.kt` best-source order (one block).
**Done when:** `render --area matterhorn --source best` uses swissALTI3D (provenance), the summit elevation matches 4478 m within 5 m, a `compare` at the border shows the seam feathered with no step over 2 m, `tour` 52/52; `check` green.
