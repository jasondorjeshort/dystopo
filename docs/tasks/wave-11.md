### T67. Users on the server and trip sharing
**Goal:** the always-on peer serves more than one person. The server config maps bearer tokens to user ids (`users: [{id, token}]`, plus an admin token); each user gets their own sync replica (`out/sync/<user>.db`) and `/sync*` is scoped by the token; the catalog, builds and tiles stay shared; `/healthz` counts users and replicas; a `dystopo users` admin command (or `server --add-user`) that generates a token. Trip sharing: `POST /sync/share?route=<id>` on the server creates a read-only share link (`/s/<token>`) that serves the route's GPX and a small web page with the route on the live map; the phone's trip card gets "Share link" that asks its server peer for one and copies it; links can be revoked (`DELETE /sync/share/<token>`); everything documented in SERVER.md.
**Owns:** `server/**` (config, users), `serverlib/.../SyncRoutes.kt` and new `Users.kt` and `ShareLinks.kt`, a new `shared/.../sync/ShareLinkOp.kt` only if a share-link op is needed (T65 owns the rest of `shared/.../sync/`), `androidApp/.../sync/**` and `trips/**` (Share link button), `docs/SERVER.md`, `devtool/.../SyncCommand.kt` (`--token` per user).

### T72. Sync over the internet: TLS, discovery and a public peer
**Goal:** sync between phones that are not on the same network, without a central account. The phone can act as a peer behind the server: `POST /sync/relay` lets two phones with the same share code exchange bundles through the server without the server merging them into a user replica (the server stores an encrypted blob per code for a limited time); bundles are encrypted end to end with a key derived from the share code plus a per-session nonce (a small pure-Kotlin ChaCha20-Poly1305 or XSalsa20, with test vectors; no new dependency); the Share screen gets a "via server" option that shows the code; the LAN link is upgraded to the same encryption so the plain-HTTP note from T54 is closed. Document the threat model in PLANNING (what the server can see: nothing but sizes and timing).
**Owns:** `shared/.../sync/crypto/**` (+ tests), a new `shared/.../sync/EncryptedBundle.kt` (framing; T65 owns the rest of `shared/.../sync/`), a new `serverlib/.../RelayRoutes.kt` (one registration line in `LiveTiles.kt`), the relay block of the `server/` config (T67 owns the users block), `androidApp/.../share/**`, the Sync section of PLANNING, the relay section of SERVER.md.
**Done when:** two emulators on different "networks" (no adb forward between them; only the server reachable) exchange a track through the relay with identical GPX; the server's stored blob does not decrypt without the code (a test); the LAN link refuses an unencrypted client; crypto test vectors pass; `check` green.
**Status: merged (PR #71).** Pure-Kotlin ChaCha20-Poly1305 and HKDF with RFC vectors and a JDK cross-check; 16-character codes on both links; relay verified phone to phone through a server that sees only ciphertext. Follow-ups: relay share links, PAKE, relay in pack-mode serve, persistent blobs.
