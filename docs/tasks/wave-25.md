### T199. The home site: the installed server and a TLS proxy as Windows scheduled tasks that start with the PC
**Goal:** `tools/site/` (new): `install.ps1 [-Root <folder>] [-Name <suffix>] [-Port <n>] [-Host <name>] [-Firewall] [-Update] [-Uninstall]` (defaults `~/.dystopo/site/`, no suffix, 8801, `localhost`). It snapshots the server distribution (`./gradlew :server:installDist :tilebuild:installDist`, copied to `<root>/server/` and `<root>/tilebuild/` so a build in any checkout never alters the running site; `-Update` rebuilds, re-copies and restarts), writes `<root>/server.json` from the template `tools/site/server.example.json` (bind `127.0.0.1`, the port, `cacheDir` and `outDir` under the root, a generated token, `publicUrl` from the host, the JSON log under the root with `log.maxMb`/`keep`), writes `<root>/site.env` (the host, the token, the JDK path snapshotted from `JAVA_HOME` at install time, `JAVA_OPTS=-Xmx2g`), downloads Caddy (Apache-2.0; the official Windows amd64 release asset, checksum checked against the release's checksums file, which proves integrity only; a runtime download `licenseCheck` does not see, said so in the docs) into `<root>/caddy/` and writes its Caddyfile from `tools/site/Caddyfile` (the host through a `{$...}` placeholder; `reverse_proxy 127.0.0.1:<port>` with the headers of `docs/SERVER.md` › Behind a reverse proxy; `respond /metrics 403` as the manual's monitoring section says, since `/metrics` exposes the log path and disk figures; `skip_install_trust` in the global block so a hidden task never prompts to trust the internal CA; Caddy's `XDG_DATA_HOME` and `XDG_CONFIG_HOME` under the root). It registers two Task Scheduler tasks, `Dystopo site server<suffix>` and `Dystopo site proxy<suffix>`, for the current user with logon type S4U and an at-startup trigger (no stored password, no window, runs before anyone logs in, so a reboot after an update brings the site back), `ExecutionTimeLimit` 0, allowed on battery and not stopped on battery, restart on failure every minute; the server action is `java.exe` from the snapshotted JDK with the distribution's `lib/*` classpath and `JAVA_OPTS` (not `server.bat`, whose `cmd` orphans the child; a `Stop-ScheduledTask` is a hard kill with no graceful shutdown, said so in the docs). If S4U registration is refused without elevation, the script says so and the owner runs it once elevated (the same run as `-Firewall`, which adds the inbound rules for 80 and 443 and is the only elevated part). `status.ps1 [-Root] [-Name]`: both tasks' state and last result, `/healthz` direct and through the proxy, Caddy's certificate state, the server's uptime and request counts from `/stats` as numbers, exit 1 on any failure; it prints status words and counts, never log lines or URLs. The public `outDir` starts empty: every view renders live; the owner builds public packs from the page with the token. Docs: `docs/reference/home-site.md` (new; the install, the owner's three steps outside the script: forwarding 80 and 443 on the router to this PC, the dynamic-DNS updater, power settings so the PC never sleeps; where the token is; `-Update` after a merge; the always-on cost in RAM), a pointer subsection "Windows: the home site" in `docs/SERVER.md` › Operations, the port, folder and RAM rows of `docs/reference/machines.md`, the index line of `docs/reference/README.md`.
**Owns:** `tools/site/**` [no-check: new folder], `docs/reference/home-site.md` [no-check: new], the new subsection of `docs/SERVER.md`, the rows of `docs/reference/machines.md`, the line of `docs/reference/README.md`. `ServerConfig.kt` already has `bind`, `publicUrl` and the log cap (critic); a key found missing is a few lines there, named in the report.
