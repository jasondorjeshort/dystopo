# 0026, sibling: formats, the reader's additions, the carried text, the build and the migration

Companion to [ADR 0026](0026-brainstorm-offer-and-rest-pile.md). What a coder and a tester build
from, in the order of section 4. Sibling names are allowed here: a decision is a closed record.

## 1. Formats (the `brainstorm` skill carries these; the rule file names the prefixes)

Header of an offer, numbers read from `node .claude/hooks/queue-list.js ideas --json` at the
session's start (open: the rows; resting: `rest` true; offered and unanswered: `offered` true with
`block` `question`):

```
Ideas: 42 open, 3 resting, 5 offered and unanswered (at the session's start); bar step 3: not one
use of a named primitive. 3 near-term, 2 intermediate, 3 moonshots; 1 entry on an existing file;
held back: 4, ask to see them.
```

Then at most nine numbered lines, grouped near-term, intermediate, moonshot, one or two lines each,
naming the anchor in path form. "Held back" counts candidates below the bar or beyond the nine that
were not shown; they stay with the session. Closing line, after a triage only, when a `rest` row
exists and the last review record is seven or more days old or absent: `Rest review? <n> resting,
last reviewed <date or never>.`

Each of the following is one physical line.

- Source line, the first body line after the title. Accepted: `Source: <who>, generated by <model
  id> and recorded by <model id>, <the public trigger>; offered and accepted by the owner; not
  sanity-checked.` Unanswered: the middle clause reads `offered <date>, not yet answered by the
  owner`; a later "record" makes it `offered <date>, accepted by the owner <date>`. `Moonshot.`
  closes the line when the idea is one. `coordinator (<model id>)` replaces `<who>, generated by
  ... and recorded by ...` when the two models are the same. The owner's own idea: `Source: the
  owner, <context>`. The trigger is named in public terms: a triage, a wave close, a release, a spark.
- `Came up again: <date>, <source> (<model id>), <context>.` Only for an independent source: the
  owner, a report, a finding, or a model that no Source line or entry on the file names.
- `New: <date>, <source> (<model id>): <angle, scope, anchor or constraint>.`
- `Use: <date>, <source> (<model id>): <the use>.`
- Rest line (a block): `Waits: at rest — "<the owner's words>" (the owner, <date>)`.
- Offer question (a block): `Question: offered <date> and not answered: record, record at rest, fold
  into <file>, or no?` then a line `Answer:`, blank. `<file>` is the matching file the cheap check
  found, else the words "a named file". An unanswered file that was offered as an entry also names
  that file in `related:`; nothing is written into the other file.
- Records, as a commit subject, or one body line of a wrap-up commit:
  `Ideas: brainstorm offer <date> (<trigger>): offered <n>, recorded <n>, at rest <n>, entries <n>, unanswered <n>`
  and `Ideas: rest review <date>: listed <n>, kept <n>, woken <n>, deleted <n>`. Read with
  `git log --grep "^Ideas: brainstorm offer 20" --format=%B` (the pattern matches a subject or a
  body line: a runner's case gave two matches for one subject and one body line; the date keeps a
  message that quotes the format from matching). The last review's date:
  `git log -1 --grep "^Ideas: rest review 20" --format=%cs`.

The bar, read once at the session's start from the row count, resting and unanswered included.
Guidance: it never refuses; an offer below it states its reason.

| Step | Open ideas | What an offered idea also shows |
|---|---|---|
| 1 | under 20 | an anchor in the tree |
| 2 | 20 to 40 | no existing file says it (else a `Came up again:` or `New:` entry) |
| 3 | 40 to 80 | it is not one use of a primitive a file or this list names (else a `Use:` line) |
| 4 | 80 to 160 | its lever: what it unblocks or answers, or why a moonshot is worth carrying |
| 5 | 160 to 320 | which open idea of its kind it outranks, one line of reason |
| 6 | 320 and up | the owner asked for its topic, or it recurred from an independent source |

## 2. The reader (amends `0017-queue-list.md` sections 2, 3 and 5; additions only)

No flag, exit code, existing field or `problems` entry changes. `findings` and `operator` rows gain
nothing and their `warnings` is always empty.

`read('ideas', abs)` also returns, computed over the body lines outside the frontmatter and outside
fences (the fence rule `blockOf` uses), whatever `kind` and the frontmatter say:

- `recurrences`, `news`, `uses`: integers, the lines that start `Came up again: `, `New: `, `Use: `
  (the prefix and one space), wherever they stand.
- `rest`: boolean, `block` is `waits` and the opener line (the last opener, as `blockOf` finds it)
  starts `Waits: at rest`. `offered`: boolean, `block` is `question` or `answered` and that line
  starts `Question: offered `. Both false when `block` is `?` or anything else.
- `warnings`: an array of `{ line, text }`, `line` 1-based in the file. W1, for each entry line
  after the first opener line: `entry below the block (move it above; a line under a blank Answer:
  reads as the answer)`. W2, for each entry line whose next line is non-blank and not an entry line:
  `entry not followed by a blank line or another entry (one physical line; a wrapped line that
  starts with a block word opens a block)`. A warning never puts `?` in a field and never changes
  `--check`.

Output: `--json` rows for `ideas` carry `file`, `kind`, `block`, `rest`, `offered`, `recurrences`,
`news`, `uses`, `title` (the five names promised with the others, ADR 0013); the text and
`--markdown` forms gain the same columns before the title, unpromised as before. Stderr, wording
unpromised: `queue-list: <file>: line <n>: <text>` per warning, in every `ideas` run, filters
notwithstanding. `post-edit.js`, in `queueLines` (so under a valid marker, as for `?`): after the
problem lines, `post-edit: <rel> line <n>: <text>. See the brainstorm skill.` per warning of the
edited file. Known false positive: a block's own line that starts with an entry prefix; the rule
file forbids such a line.

Harness, group `Q`, fixtures added to the scratch `docs/ideas/`; the existing cases keep their
meaning, and Q04, Q05 and Q08 take the new columns in their expected `ideas` text and markdown:

- Q14 fields, `ideas --json`: `Waits: at rest — "not now" (the owner, 2026-02-09)` reads `waits`,
  `rest` true; the existing `Waits: a second contributor.` reads `rest` false; an offer Question
  with a blank `Answer:` reads `question`, `offered` true; the same answered reads `answered`,
  `offered` true; the existing `Question: which shape?` reads `offered` false; a file with two
  `Came up again:` lines, one `New:` and one `Use:` above a `Plan:` reads `plan`, 2, 1, 1; the same
  three prefixes inside a fence read 0, 0, 0; that clean file prints no warning; `--check` exits as
  before.
- Q15 a `New:` line below a blank `Answer:` (review case 05): stderr W1 with its line number;
  `block` still `answered`; `--check` exit unchanged by it.
- Q16 a `New:` line wrapping onto a line that starts `Plan:`, in a file with no block (case 10): W2;
  `block` `plan`.
- Q17 under `Waits: at rest`, a `Use:` line wrapping onto a line that starts `Plan:` (case 14): W1
  and W2; `block` `plan`, `rest` false.
- Q18 hook: an edit to each of the Q15, Q16 and Q17 files under the marker README prints the
  `post-edit: ... line <n>: ...` lines; an edit to the clean Q14 file prints none.

`0002-hook-specs.md`, section 2, the message table: two rows for the post-edit lines (W1, W2), in
the coder's commit.

## 5. Migration (ADR 0013: the idea grammar's first incompatible change)

Every file written before reads as it did, and no older reader misreads a new one: a rest is a
`Waits:`, an offer Question is a `Question:`, entries are body text. The base-owned parts arrive in
one update, so no tree has the skill without the rule file and the reader. The project-owned part
is three sentences of `docs/ideas/README.md`:

1. The `Waits:` bullet: "the owner's deferral: to a trigger it names, or, as `Waits: at rest`, until
   the owner wakes it. Only the owner decides one; the session the owner answered writes it from
   their quoted words."
2. Under what drains the queue: "A pass builds a `Plan:` or an answered `Question:` only when no
   `New:` line stands above it and the Question is not an offer (`Question: offered`, which the
   coordinator acts on), and deletes the file only when no `Use:` line remains; otherwise it
   removes the block and the file is untriaged again."
3. "Offered ideas, the Source line and the entries (`Came up again:`, `New:`, `Use:`): the
   `brainstorm` skill."

The skill applies them: before its first offer in a tree it checks `grep -c brainstorm
docs/ideas/README.md`; at 0 it writes the three sentences and they ride in that offer's commit.
