## This agreement is part of the work

Designing the base is itself the project. When a step is awkward, an agent brief is missing
something, a hook misfires, or a better way turns up, fix the protocol in the same sitting:
edit the agreement file that carries the rule (in Hatchery; in a project that is a departure), the agent definitions, the skills, or the hooks, and commit the change with the
reason in the commit message. Do not carry process friction forward as tribal knowledge.
The agreement states rules. A lesson too specific for it becomes an ADR (`adr` skill) if
it is a choice, or in the relevant skill if it is a procedure; how a mechanism works goes in
`docs/reference/` or the ADR that chose it, with a pointer from the agreement.
The agreement files in `.claude/agreement/` are edited in Hatchery only. In a project, a fix to a
base-owned file is a departure: a row in the departure table and a carry-back idea, same sitting.
